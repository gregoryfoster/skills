- **Slotted mid-run:** the diff's presentation fix, three build-gate issues, a gate-coverage issue (about 40% of the suite ran in no gate), a three-link residual chain (CannObserv/watcher#361, CannObserv/watcher#362, CannObserv/watcher#363), and a dated CI-image check filed at close-out.

### What was different

- **The goal named something already closed.** The diff's issue had closed the day before, but no real email had carried a diff yet. The goal became a verification-debt line, a guard issue and a standing probe.
- **The deciding event had no owner and no date.** Two gates waited on a watched page changing. The epic wrote the reorder in advance, and the operator carried it out between check-ins without the coordinator.
- **The epic nearly reverted itself.** A failed transform left a stale output file that the next command would have published, one day out of date.
- **The exit criterion was met with four items still queued.** The operator chose to finish the queue.
- **A long run of residual bugs** was closed by sweeping the class, after the second link.

### Findings that changed the protocol

**Creation**
- When the operator's goal is "X working", check whether X is observed working, not only whether its issue is closed (F1).
- Measure the verification's precondition at creation, so the first real event decides it (F2).
- A default test config can deselect half the suite: `1586 passed, 1118 deselected` read as a full green run. Record each marker set's command and count (F4).
- Grep the host's own recent comments for future-tense promises ("we'll ask", "at the next") that no issue tracks (F5).
- Classify sibling mentions by "does anything stop moving until we act?". Of 49 mentions, 5 waited on watcher, and none asked a question (F6).
- "Move" is a fifth disposition: prove ownership in code, carry the repro, put each open question where it can be decided, and close with pointers both ways (F7).
- "Not planned in v1" is a park with a trigger. Superseded means the need is gone (F8).
- Offer one multi-select question for the creation writes, and expect the operator to split it (F9).
- Fill placeholders with `str.replace`, never `sed`; a URL fragment's `#` broke the pattern. Run the ref check after the fill (F10).
- Assert that the created epic's number matches the watermark the body predicted, and PATCH if it doesn't (F11).

**Verify**
- The unit of verification is the commit range on `main` since the last tick, each commit attributed: child, bot, curation, out-of-band fix or telemetry (F39).
- When production has outrun the check-in, verify against what production did. A user-facing outcome ends with the operator's own observation, asked for explicitly (F19).
- A verification line states the acceptance (delivered and useful), not only the event. A 12.5 KB diff burying a 60-character change passed one and failed the other (F16).
- When `/health` doesn't name HEAD, ask whether the diff between them touches anything the process loads (F20, F58).
- Read CI annotations for calendar signals, and record a red run's cause on the line at the tick, because job logs expire within a day (F27, F28, F42).
- "The acceptance as written could not hold" is a claim to check, then tick if it holds (F26).
- Compute a gate verdict over a closed window, `[start, end)` (F40).
- For each part of the suite, record which gate runs it. Check an exclusion's recorded reason against the code (F29, F30).
- When comment creation fails, an implementer may write into the issue body. Read the body as it stands and its edit history, as well as the comments (F23).

**Harvest**
- An implementer's measurement caveat becomes a standing check with a target window and a before-figure (F46).
- A standing check needs a state it can reach. Note it when the run's own cadence starves it, as when every child restarted the service (F50).
- A missed window can still decide the question if the miss biases against the expected result. Write which direction stays decisive (F62).
- Verification debt with no expected event is marked "not live-exercised", with its log signature added to the standing probe (F38).
- Route an implementer's suggestion for a skill through the coordinator, then the operator, then upstream (F35).
- Holding a cross-repo claim as "recommendation only" until it's checked against the sibling's code let a wrong claim die quietly (F47).
- A one-off premise check can become a permanent guard. A brief can add "if it holds and is cheap to enforce, make it permanent" (F36).
- The same code-review stet in two consecutive close-outs points at the kickoff prompt, not the implementer (F31).

**Re-scan**
- List everything updated since the last check-in, not only numbers above the watermark. Each standing probe records its expected steady-state output, so a probe that goes quiet reads as a signal (F13).
- Re-run every live-state probe in the same command chain as the write. The awaited event landed six minutes before the epic said it hadn't (F12).
- When a child changes what the system logs, rewrite the probes in that tick (F15).
- Watch a gate issue's `updated_at`, not only the release signal it names (F55).

**Blockers and gates**
- Write the reorder for an unowned, unscheduled event in advance, so the check-in that sees it acts without asking (F3, F14).
- When a child deletes a capability, re-read every parked row's need against the deletion, not only its trigger (F54).
- When a sibling replaces a lockstep with "notice, or coordinate on contract changes", check each pending upstream release against its contract list (F57).
- An implementer's follow-ups can change the ordering rule. "A guard goes before what it guards" became a written tiebreak (F22).

**Hand-off**
- A redesign's brief lists the defences of the design it replaces. Grep the old design's review rounds for hardening a simpler shape would drop (F17).
- Re-derive a cleanup inventory by grep at hand-off. Three orphans were five, plus a CSS layer (F21).
- Check every writer of the state a proposed hook observes. A reconcile path bypassed the setter, so the hook would never have fired in production (F24).
- Derive a deploy order from the migration's shape: additive migrates first, a column drop restarts first (F45).
- An evidence level on a brief claim (`[stated]`) let the first real run test it, and saved the operator an admin step (F41).
- Track a shared doc's token headroom on the epic, like any other shared surface (F37).
- When the coordinator files an issue with the operator's decision already made, the body carries the decision and the brief. The issue is the hand-off (F49).
- At the second residual of the same shape, sweep the class. List every caller, classify each by the hazard's preconditions, and post the table on the issue (F51, F56).
- Measure exposure with the full denominator: "0 of 1758, while 6 failed another way" (F53).

**State and writes**
- Transform and write form one `&&` chain. Delete the output first, and derive expected counts from the input body (F43).
- When a foreign edit shows up, transform the live body. The baseline only detects (F44).
- Make each write conditional on its check, and quote every heredoc that carries Markdown. An unquoted one ran backtick spans as commands (check-in 1).
- The epic body needs its own ref check. Flag a bare ref after a qualified one, and any bare ref above the host's highest number (F61).

**Operator**
- Put measured usage beside each decision question. The operator went against the recommendation twice, and no follow-up was needed (F25).
- When a new issue supersedes a bundling decision, re-ask once and record the answer with its date (F18).
- A code comment that says "deliberately not" is a prior decision. Reversing it goes to the operator, even for a one-line fix (F48).
- Precedent narrows a question without answering it. Ask again when the reason differs, and say how (F52).
- A brief carries only approved process changes. Draft it after the decision question (F34).
- "Exit criterion met" and "queue empty" are separate events. Say when the criterion will be met, and ask once when it is (F32, F33).
- A documented mechanical procedure, such as landing a bot PR by the repo's own steps, is within the coordinator's reach with consent (F59).

**Close-out**
- A check dated after the end goes to a dated issue. It doesn't hold the epic open (F60).
- Order the close-out so each step yields the evidence the next needs: the starved reading, then the restart, then CI by job, the dated hand-off, the final body, and last the summary and close. Run the account check on both the body and the summary (F58, F63).

### Reversals

- **Deploy check.** "Label equals HEAD" gave way to tree equality on deployed paths (F20). The last child changed only CI, docs and tests, and tree equality also failed. It was replaced by "does the diff touch anything the process loads" (F58), which won.
- **Unit of verification.** The broker run's `#N` grep would have missed most of a thread's work. The range since the last tick replaced it (F39).
- **Transform source.** The transform first ran on the stored baseline. A foreign tick would have been silently undone, so it now runs on the live body and the baseline only detects (F44).
- **Close or park.** The coordinator recommended closing an issue whose page v1 rules out. The operator parked it, and "deferred is a park" won (F8).
- **A proposed kickoff line.** "Commit the failing test first" went to the operator as a suggestion (F31) and leaked into a brief before the answer. The operator didn't adopt it, and it was edited out (F34).
- **Starved check.** F50 waited for the window to come round. F62 accepted a late reading because the miss biased against the result it found.
- **Shipping.** On the cross-repo parent below, the implementer no longer ships. It runs a fixing review, reports and pauses for the operator (368-F1).

### What v1's scripts would and wouldn't have caught

- **Would:** `scan.sh`'s updated-since cursor and commit range cover F13 and F39. Its cross-repo ref report gives each ref's state and last activity, which covers F55's gate issues.
- **Would:** `epic-edit.sh` transforms in memory on the live body and derives counts, so there's no stale output file to publish (F43, F44). Its lint flags a bare ref after a qualified one and a bare ref above the highest number (F61), and unfilled placeholders (F10). `--account` repeats the creation check that every open issue is listed.
- **Wouldn't:** posts to other repos. The bare ref in a comment (F35) and the unquoted heredoc (check-in 1) happened outside the epic body.
- **Wouldn't:** live probes in the write chain (F12), `/health` against HEAD (F20, F58), gate coverage (F29) or CI annotations (F27). None of these is a body or tracker read.
