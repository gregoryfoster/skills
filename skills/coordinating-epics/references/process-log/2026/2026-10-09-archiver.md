## Session 2026-10-09 — CannObserv/archiver#300

The first coordinator run, and the one the skill's shape came from. The epic was built from a design doc whose Steps table was the plan. It closed on 2026-10-09 after an operator-run cutover. The same thread then kept coordinating the epic's follow-ups, and on 2026-10-10 it drifted into implementing one of them (finding 60). As of 2026-10-14 the epic is closed, and its follow-ups are tracked outside it. Findings 1–7 are in the body of gregoryfoster/skills#348. Findings 8–57 were posted after each check-in, 58–59 with the closing synthesis, and 60 a day after close.

### Shape

- **Way in:** inherited from a design doc. Its Steps table gave the children and their order (5), and the coordinator created the epic and the children from it.
- **Children:** 9 planned and 4 slotted mid-run. Two were code-review follow-ups filed by an implementer, one was a duplicate scoping issue from a parallel thread (closed as delivered), and one was a refactor follow-up. There were 3 cross-repo dependencies (a Power Map API change, its SDK and an API key) and 1 operator-run cutover.
- **Check-ins:** 13, over 8 days (2026-10-02 to 2026-10-09).
- **Cost:** about 10–20 tool calls per check-in, mostly verification. The coordinator never touched code. Its only repo writes were two docs PRs amending the design.

### What was different

- It was the first run. There was no protocol and no script, so every rule was found by doing a step by hand or doing it wrong.
- The design doc set the order. The coordinator added tie-breaks only where the design was silent (24, 26, 48, 50).
- Cross-repo blockers dominated the middle. After check-in 7 no child was unblocked, and the epic cleared in two stages: the SDK shipped, then the key arrived.
- The last child was an operator-run cutover, so the run ended by compiling a runbook (55).
- The thread outlived the epic. That is where finding 60 happened.

### Findings that changed the protocol

**Creation**
- The design's Steps table is the plan (5). Cross-references between children not yet created go in as `SUBn` placeholders and are substituted after creation, by a script, not a regex typed live: a lookbehind that excluded `/` missed `SUB7/#8` (1).
- Check native sub-issue links against the list itself. `sub_issues_summary` lagged behind it (3).
- Read a label's description before applying it. `no-changelog` went onto an issue by reflex, though its description says it opts a PR out of a CI gate (4).
- A refinement found while writing the children is written back to the design doc and the epic in the same pass. Here a function signature changed from `(item, org)` to `(bag, org)`, so it stays pure (6).
- Each cross-repo blocker records its owner (7), an observable unblock condition (22, 28), and the stages it gates: merge, verify, deploy or downstream (43).
- File the design's "file X separately" promises at creation, as blocked issues, so the scope boundary exists in the tracker from day one (59).
- Assumptions about an artifact that doesn't exist yet go in the design's risks, flagged for re-check on arrival. The design guessed the SDK would ship as a wheel; it shipped as a git tag, which changed the deploy prerequisites (42).

**Verify**
- Verify by deliverable type, on production, read-only. A migration means `alembic_version`, a route means the served OpenAPI, a timer means its journal, and a deploy means a restart after the merge (8, 31, 49).
- The host's gates are necessary but not sufficient. A path-based changelog rule passed a change to an error `code` that clients see. Check every wire-visible value, and raise it as a judgment call (25).
- The coordinator ticks "Done when" itself, on evidence (9).
- At every check-in, check that the main checkout is on `main` and clean. One implementer worked in the production checkout, so a single restart would have deployed unmerged code (52). Report what failed separately from what could have (53).
- Verify an implementer's answer to a later child's step before recording it where that child will read it (47).

**Harvest**
- Diff the contract the epic assumed against the one that shipped, and write each change to every downstream child and the design (14, 20). An implementer's pre-implementation review rewrote a lock order, a 409 contract and a request shape. This was the coordinator's most valuable work.
- Relocate implementers' `For #N:` notes to the issue they name (19, 32).
- Ask whether the child added a state, code or message that a later UI or SDK child must render (27).
- Keep a verification-debt ledger with what, why skipped, how to discharge it, and discharged-by (18, 33, 37). A later child can discharge a debt. Debts that share setup are sequenced together (56).
- Route accepted limitations to the issue where a human will meet them (38). Point the next child at the doc section that holds a design rule rather than restating the rule (34).

**Re-scan**
- Scan by number watermark, issues and PRs together, and record it in each check-in. A search by creation date returned nothing, while the watermark found follow-ups that never mentioned the epic (10, 17).
- An issue that claims the epic but isn't linked is either slotted or closed as delivered, with evidence. Either way it gets linked (45).
- When the operator reports out-of-epic work, check it and say it isn't a child (44). Cross-link it where it changes a remaining step's preconditions (57).

**Blockers and gates**
- Re-check by probing. Read the latest comment, not only the state (21). Test the observable condition, here the 410 declared in the served `/openapi.json` (22, 28).
- Read an upstream blocker's closing comment for a `For <consumer>:` section, and turn it into write-backs (29).
- A newly available upstream artifact gets an integration checklist: the tag, the served build, the signatures, the dependency ranges and the auth defaults (41).
- Probe for an operator prerequisite rather than waiting to be told. For a key: the variable's presence and length, plus one read-only call. Never its value (46).
- Check what the operator said they would file elsewhere, and report it neutrally as status (40).

**Hand-off**
- Pre-flight the next child against `main`: what it renames or removes, and what references that today (30). The pre-flight items all came back handled in the implementer's report (36).
- Name the docs PR or stacked branch the next child depends on: "merge #N before #M" (13, 16, 23).
- Tie-breaks after the design's order: context freshness (24), one migration at a time (26), safety net before capability (48), and renaming deploy-visible names while the thing is idle (50). Don't under-rank cleanup children; a "just move a module" child found a latent crash (54).
- Warn when the next child is the last unblocked one (35). When the whole epic is blocked, hand off the blockers, their owners, the visible evidence for each and the options, in place of a next child (39).
- Announce a known-red window between a merge and the host step that clears it (51).
- The kickoff prompt carries the implementer contract: work in a worktree, tick "Done when", write `For #N:` notes, list skipped verification, record accepted limitations, and write the post-merge host steps into the issue (synthesis).

**State and writes**
- Every epic body edit goes through one guarded step: fetch live, transform, refuse an empty or unchanged body, then write. An empty body file blanked the epic (2). A failed transform that wasn't `&&`-chained still let the write run (12).
- Edits are idempotent and tolerant of concurrent change: "tick if unticked", never "replace this exact old text" (11).
- Write back to children as comments, not body edits. A comment only appends, so it can't race a concurrent edit (15). Design amendments go through a docs PR (16).
- State lives in GitHub, in check-in comments that carry the watermark. Host memory is only a pointer (synthesis).

**Close-out**
- Closing checks: every sub-issue closed; every unticked line ticked, moved to a follow-up or marked out of scope; the cutover re-verified independently; and the implementers' unfiled observations listed for the operator (58).
- Before an operator-run final child, compile one runbook: debt to discharge on dev, production steps, read-only verification, then expected quirks. Tag each item with the child it came from (55, 56).
- The coordinator writes no code. On any request to implement it asks "here, or in a separate thread?" and defaults to a separate thread. When the thread keeps coordinating follow-ups, the closing summary restates the role. Prerequisite work is coordinator work: cross-repo issues, operator setup, key handover and peer-agent coordination (60).

### Reversals

- **New-issue scan.** The first rule was a search by creation date. It returned nothing, so the number watermark replaced it (10, 17). v1's `scan.sh` keeps the watermark and adds `updated_at` since and the commit range, because later runs each missed something with one cursor.
- **Epic edits.** The first edits matched exact old text, and concurrent edits broke them. Idempotent operations replaced them (11). v1's `epic-edit.sh` anchors by ref.
- **Write-backs.** The first write-backs were body edits. Comments replaced them, and body edits are now kept for checklists the coordinator owns (15). The comment rule is in v1.
- **Unblocking.** At first an upstream issue closing counted as unblocked. An observable condition, recorded when the blocker is filed, replaced it (22, 28). The observable condition is in v1.
- **Design assumptions.** The design stated a guess about the SDK's distribution as a decision. That guess now belongs in the design's risks, to be re-checked on arrival (42).
- **"Proceed."** After the coordinator had done the prerequisite work, it read "proceed" as permission to implement. The replacement is to ask, and to default to a separate thread (60). v1 makes this the Iron Law.

### What v1's scripts would and wouldn't have caught

- **Would have caught the body accidents.** `epic-edit.sh` transforms the live body in memory and writes nothing when it refuses, so neither the blank epic (2) nor the failed transform that still wrote (12) could happen. The baseline diff refuses a concurrent edit, and anchoring by ref survives a tick made elsewhere (11).
- **Would have listed the stray issues.** The watermark in `scan.sh` lists the unlinked follow-ups and the duplicate scoping issue (10, 45). Its cross-repo report would have flagged the Power Map blocker as updated since the last check-in (21). It reports state and activity only, though. The amendments in the latest comment, and the 410 in the served OpenAPI, still had to be read (21, 22, 28).
- **Partly on creation.** The lint catches an unfilled `SUBn` or `{{…}}` placeholder in the epic body (1). Children's bodies are created outside v1, since `create-from-plan.py` is v1.1. Neither script checks `sub_issues_summary` (3).
- **Wouldn't have caught anything on the host.** That covers the production checkout on a branch (52), the migration head and the timer journal (8, 49), and the key's arrival (46). Neither script verifies a child. The synthesis proposed `verify-child.sh`, and v1.1's `verify-ci.sh` covers CI only.
- **Wouldn't have caught the drift into implementing** (60). That is a role rule, and no script checks it.
