## Lessons

### 1. Grep the mechanism an issue names across the whole repo, not the files it names

#544 said "no module under `worker/` installs a SIGTERM handler" for source workers. Grepping `import signal` repo-wide showed no worker process of any kind has a handler. An `app/launchers/consumer.py` docstring (in another package) asserted that consumers emit `STAGE_CANCELLED` on SIGTERM, which is false. The widening came from a docstring contradicting code in a package the issue never mentions. This is a variant of "an issue body's hedge is a grep target": here the unverified claim sat in the *code's* prose, not the issue's.

**Held (#285): the understate direction of a grep the skill already prescribes.** Step 5 item 1 greps "the contested symbols/keywords" in both directions, and "bodies understate scope" has carried 2026-05-09's five-times-larger dedup fix since May. Followed as written, it produces this widening. Two things are sharper here. The first is the *key*: a negative claim bounded to a directory ("no module under `worker/`…") becomes a grep target once the bound is dropped, and the grep runs on the mechanism (`import signal`), not on the issue's symbol. 2026-08-16 skills logged the neighbouring form ("an issue can name one file and require two read … only visible if you grep the claim rather than the filename"), so this is the second sighting of the technique. The second is that the false claim sat in a docstring. Step 1–2's "docstrings cut both ways" has two edges, one crediting the PR that retired a footgun and one naming pending follow-ups, and this adds a third: a docstring can simply be wrong. This lesson is recorded under its own heading so that a third sighting can find it.

### 4. With a 2-slot ceiling and many units, write the plan as exclusion groups plus a queue, not only fixed pairs

The fixed wave pairing is the default. Naming the never-concurrent sets (per hub file, per shared doc) is what makes rolling fill safe to run: the orchestrator can pull a later item forward without re-deriving the conflict map. The gate suite runs before a freed slot is refilled, which keeps suite concurrency at the ceiling.

**Held (#285), pending execution.** There is one sighting, and the plan has not yet run. The lesson's safety claim, that a later item can be pulled forward without re-deriving the conflict map, is a prediction, and the execution addendum is where it gets tested. If it holds, it refines Step 7's "chunk when N > ceiling", which prescribes fixed sub-waves. It also generalizes a promoted principle, 2026-08-11 observo's "a zero-conflict issue fills whichever slot would otherwise idle", from one issue to a queue.
