### Closed-in-fact has a date axis, not just a grep axis

The strongest finding, and the existing rule would not have caught it.

Step 1–2 prescribes grepping each issue's identifying symbols. For **#164**
("nothing in the pipeline validates link anchors") the grep came back
*loud* — `links.dead_anchors` everywhere, a dedicated `test_context_anchors.py`,
telemetry and gate plumbing. Not zero hits, not ambiguous: the fix was plainly
present. The question that actually resolved it was **when**:

| | |
|---|---|
| Fix landed | `33c43cd`, **2026-08-11** |
| Issue filed | **2026-08-14** |

Three days *after*. The issue was filed from
`CannObserv/cannabis.observer-wordpress` — pinned at skill **v1.3**, which predates
the fix. Every green check the reporter observed was real; it was the consumer's
pinned version, not this repo's `main`.

**A defect report arriving from a downstream repo carries that repo's pin, not the
upstream `main`.** The issue read as freshly-filed and authoritative — it even
supplied a working reference implementation and two slugger gotchas — and all of it
was already in the tree, including both gotchas and the "scope note" it framed as
future work. The disconfirming evidence was a date comparison, not a symbol.

Cheap check, and it generalizes past this repo: `gh issue view N --json createdAt`
against `git log -S'<symbol>' --format=%ad`. Any repo whose issues are filed by
consumers of a versioned artifact has this failure mode.

### Shape A justified by contradiction, not by file sharing

#118 and #168 were bundled into one agent. They do share files — `.skills/cohort`,
`validation-gate.md`, and **106** `wave:`/`pair:` references in `score-cohort.sh` —
but that is not why.

They **contradict**. #168 argues the wave A/B split is unrecoverable (zero
`.skills/skills-pin` anywhere, four of six pairs inverted). #118's own last comment
refutes the premise it rests on: CI checks out with `submodules: recursive`, which
resolves the **committed gitlink**, so for scheduled runs the pin is authoritative
and a wave *can* hold a version. Neither issue's author noticed they had answered the
same question two ways, because the correction was filed as a comment on one of them.

The existing Shape-A heuristic is "naturally sequenced, define → use." This is a
third trigger: **two issues that will each answer the same open question, separately,
must be bundled — deciding it twice in two branches is how the roster and the scorer
end up disagreeing.** Found by reading both issues' comment threads, not their
bodies; the bodies alone read as complementary.
