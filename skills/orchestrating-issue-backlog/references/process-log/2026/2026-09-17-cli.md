## Lessons

### 1. A closed upstream prerequisite is not a landed one

#1010 was conditioned on `cannabis.observer-wordpress#822`, which was closed. Its CLI-facing
half, `cannobserv#433`, was closed too. Every issue-state signal said the precondition was met.

It was not. #433 closed on 2026-09-16, one day after the `v0.17.0` tag was cut on 2026-09-15,
so it sits in cannobserv's `[Unreleased]` section, and this repo pins `v0.16.1`. The defect
#1010 describes could not manifest at the pin, and would not have at v0.17.0 either:
v0.17.0's changelog says outright that *"the […] create and update bodies still emit none
of the three, and #433 tracks writing them."* A worker would have written a fix that could
only be verified against a mock of a response no installed version emits. Reading the pinned
dependency's changelog is what caught it; nothing in either issue's state did. #1010 was
deferred. Its re-entry condition is a release carrying #433 *and* a pin bump to that
release. Bumping to v0.17.0 was considered and rejected, because that tag does not carry it.

**Promoted ([#298](https://github.com/gregoryfoster/skills/issues/298)), as a bullet in
[`issue-audit.md`](../../issue-audit.md) beside "a closed prerequisite is not a met
prerequisite", with a clause in Step 1–2's dispositions list.** This is the second sighting of
the release axis. 2026-08-20 skills settled #207 with `gh pr view` plus `gh release list` — "a
merged PR without a release carrying it would still defer" — and recorded no disposition for
it. Two neighbouring entries reach the same axis from other directions:
- **2026-08-13 cannobserv:** the upstream blockers had closed, and their close dates showed
  that the local contract pin was stale.
- **2026-08-16 skills:** whether a defect is live is decided by a downstream reporter's pin,
  not by upstream `main`.

The issue's framing of the relation to "zero hits is ambiguous" stays in the rule. That rule
catches a false negative in the skill's own grep. This one is a false positive from every
issue-state check, and it leaves nothing negative to notice. The cheap tell is written in one
direction only. A close date after the latest tag shows that no release carries the fix, but
an earlier date proves nothing, because the pin can predate that tag, as v0.16.1 did here.
The issue's "generalizes to any repo with pinned dependencies" is left out. The rule is scoped
to an issue conditioned on an upstream change, which is what was seen.

### 2. A third ceiling source that Q5 did not ask about

Both Q5 sub-questions answered "none". `scripts/setup-worktree.sh` is a plain
`git worktree add` plus `uv sync`, and the suite is hermetic. By the skill as it stood, that
reads as a host CPU/RAM ceiling, the 2026-08-12 outcome. But the `pre-commit` hook runs the
full suite with `pytest tests/ -n 4`. Every commit by every worker spawns four test
processes, so a three-agent batch can mean twelve concurrent pytest processes on a
3,319-test suite. The plan recorded a ceiling of 3, CPU-bound, and gave that multiplication
as its reason. No contention was measured.

**Promoted ([#298](https://github.com/gregoryfoster/skills/issues/298)), as Q5's third
sub-question, with the worked arithmetic in
[`shared-backing-services.md`](../../shared-backing-services.md) rather than in the
sub-question, and a pointer from Worker step 6.** It is one sighting, admitted as a new question rather than a recurrence because
neither existing sub-question can surface it: the hook is neither provisioning nor a backing
service. The multiplier compounds Q5's capacity half (2026-09-16 wordpress). The same read of
the hook also answers Worker step 6's red-phase `--no-verify` question, which this plan
recorded as well, and putting the answer in the brief saves every worker the check. The rule
states the arithmetic, not a slowdown, because no slowdown was measured.

## Log-only observations

These are the issue's own, filed as not proposed for promotion, and they stay here.

- **One measurement moved the graph in both directions.** Measuring #1012's consumer audit
  **dissolved** an expected edge and **revealed** an unexpected one. The dissolved edge was
  #1012↔#999: the positions command looked non-compliant by line number and was already correct. The
  revealed edge was #1012↔#1007, on a file neither body connected. The rule that decisions
  move the graph (2026-08-23, 2026-08-28 power-map) held. Earlier entries recorded each
  direction on its own; here one grep did both. **Carried.** The outcome below records what
  that measurement missed.
- **A test that names the issue by number can still be vacuous.** The positions command's test
  carried the docstring *"#999 changes the title for a subtype event"*, but its fixture Event
  has no subtype, so it passes identically before and after the fix. The vacuous-assertion
  rule in [`shared-files.md`](../../shared-files.md) covers the mechanism. The refinement is
  that an issue number in a test's name or docstring is a strong *false* signal of coverage,
  because it makes both worker and reviewer likelier to trust the test without reading it.
  **Held** — worth a clause if it recurs.
- **Interview compression.** Q1, Q2, Q4 and Q5 were asked in one structured round rather than
  four sequential ones. The one-at-a-time rule rests on "stacking questions gets partial
  answers", and a structured question tool that answers each question separately prevents
  that. **Held** — flagged for a possible "unless the host tool guarantees per-question
  answers" carve-out, not proposed on one session.

  that first access. The issue body named the import commands in its own trade-off paragraph, and the pointer went unfollowed. Batch C's brief
  said "do not redo it from scratch, but verify it", which is what produced the correction.
  **Carried** — an orchestrator's grep is as falsifiable as the body it audits
  ([`issue-audit.md`](../../issue-audit.md), 2026-08-12).
- **Every issue body was wrong or incomplete**, and workers corrected two of the orchestrator's
  briefs, correctly both times. **Carried** — Worker step 5 and the report-back slot.
