## Lessons

**A prior session's defer verdict is time-varying — re-probe the blocker, not
the disposition.** #163 was deliberately deferred on 2026-08-16 because its
gate (`CannObserv/observo#457`) sat outside the repo and outside that session's
named set. This session the gate had closed **green** with all four coexistence
answers, flipping the verdict from defer to rescope-to-residual. The audit
found it only because the closed-prerequisite rule says grep the *finding*, not
the state: one `gh api` call on the external issue. A named set containing a
previously-deferred issue should open with that probe — the deferral comment
names exactly what to check.

**Measure-then-rescore: when an issue's embedded decision names its own
decider, run it during the audit.** #233's option 3 said "check the twelve
consumers first; if none carries an absolute hook symlink, this can simply
become correct." The sweep is 12 read-only `gh api` calls (symlink targets are
blob contents — the contents API's `target` field came back empty; fetch with
`Accept: application/vnd.github.raw`). Result: zero absolute links, every
managed hook already `../../skills-vendor/...` — Scope 1→3 before the
interview, and one gate question dissolved into a fact. Cheaper than the
decide-then-rescore it replaced, and it surfaced a scoping caveat the decision
alone would have missed (`context-budget-guard.sh` legitimately links through
`skills/` indirection and belongs to a different installer).

**A sibling fix can sharpen an open issue rather than staling it.** #192's fix
(install the `merge.ours.driver` in clones, verify in `--check`) made #237's
silent-revert failure mode live in *every developer clone* instead of only the
cadence job — body decay raised the issue's severity. The audit habitually asks
"did later work close this?"; it should equally ask "did later work widen
this?" — same grep, opposite verdict, and it moved #237 to the top of the
table.

**Zero closed-in-fact is still a high-yield audit.** All twelve issues were
open in fact, yet the audit changed half the plan: one rescope, one Q0 bundle,
one split, four settled decisions, and one file-location correction (#233's
script lives in `managing-skills/`, not `init-socraticode/` as its provenance
implies). "Nothing was stale" and "the audit changed nothing" are different
outcomes.

**A body marking a sub-item "independent of whatever this issue concludes" is
a split signal.** #97 carried a one-row doc fix inside an investigation issue;
Q0 split it, and the doc fix bundled naturally with #96 on the file they share.
The investigation kept Scope 1 without dragging a Scope-3 item down with it.
