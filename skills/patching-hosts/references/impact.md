# Readings, continued: impact

The [readings](readings.md) of what a run touches: which processes map a library in the set, the services and data stores behind them, and what stops or restarts with them. Each is paired with **the mistake it prevents**, as in readings.md.

| Reading | How | Mistake it prevents |
|---|---|---|
| **Which processes map a library in the set** | `sudo` read of `/proc/*/maps` against the set's shared objects. After a dry run, `maps.lane` names its lane, and each unit's `lane_packages` are the mapped ones it takes, `in_lane` whether any (#686) | "Postgres isn't in the set, so no restart": its backends mapped libc6 and libxml2 (watcher, address-validator, wslcb). A reboot read into a lane from a package it doesn't take: the security lane's map listed `libsystemd0` |
| **A third-party origin carrying a serving runtime** | `impact.maps` against each package's class: a process in a `.service` unit mapping a shared object of a pending package from a third-party origin (not Ubuntu's or Canonical's, which need no policy) makes that origin's whole pending set `exposure:<origin>`, a security exposure, not maintenance (#464). Its gap is the expedite path ([knob.md](knob.md)). Whether the process listens isn't read, since `ss -Hltn` names no pid, so a daemon or a worker counts, and a session's `.scope` doesn't. The map matches shared objects only: php-fpm is seen through the extensions it maps, a deadsnakes Python through `lib-dynload`, and a runtime that's one executable with none of its own, such as NodeSource's `node`, isn't seen. needrestart's list can't stand in: it names what runs a binary already replaced, and a pending package has replaced nothing | a runtime from a PHP PPA 8 patch releases behind for eight months under a healthy-looking posture, because `follow` takes an origin only at the host's cadence |
| Each data store's source and collation | `datcollate` and provider per database; `datcollversion` unless C.UTF-8 on libc | a collation-version change after a libc or ICU upgrade |
| **Undeclared databases** | the cluster's databases, less the templates and a `postgres` with no table of its own, against the knob's `datastore` lines | a database the recovery point doesn't cover ([knob.md](knob.md)) |
| **Undeclared Qdrant containers** | each running `qdrant/qdrant` container against the knob's `datastore qdrant` lines (#367) | a store no recovery point covers: on co-index, nothing said the host held one |
| **A Redis line with no login** | each `datastore redis` line with no user, against an `aclfile` or `user` line in its config, read as root; the finding `redis-login:<unit>` where the recovery point or the chain would refuse it ([datastores.md](datastores.md#reaching-it)) | learning at the recovery point, 3 hours before the window, that the dump has no login (host 6, #458) |
| **Live arguments** | `/proc/<pid>/cmdline`. A reading leaves the host, so `live_args` redacts, by name and best-effort (#698): the value of an option or `NAME=value` whose name's last word, split at `.`, `-`, `_` or a capital, is `token`, `password`, `pass`, `secret`, `key` or the like, or Redis's `requirepass` or `masterauth`, in any case, never a `--no-` boolean, also within an argument holding spaces (`sh -c`'s script); a URL's userinfo; a secret-named URL parameter. So is a path after a `key` word: it can't be told from a key. A value runs as a shell word (#707); left open or past 4 KB, the rest drops, marked `<...>`, in the backup log until it closes or a `+ ` line. It leaves a positional secret, a short option's value, a name off the list, a Python repr's `\'`, a quote 200 entries back and the environment unread. Check before pasting | reading a daemon's config from its journal. wslcb quoted earlyoom's boot-time block, not its last start. A tunnel token pasted into an issue with the reading |
| **A service on a replaced binary** | `impact.services[].exe_deleted`: a cgroup process's `/proc/<pid>/exe` ending ` (deleted)` is `stale-binary:<unit>`; null with no process or no root (#699) | taking an installed version as in effect: cloudflared ran the replaced binary until a reboot |
| **Boot ordering** of each service | its `After=`, and `systemd-analyze critical-chain` | a first start that succeeds by luck, and fails on the next boot (CannObserv/address-validator#239) |
| A data store's own dependency | each `depends` line: the data store's `After=` on the unit it needs up first | a Redis bound to the tailnet address that starts before `tailscaled` (#384) |
| **In-host automatic restarters** | timers or services that run `systemctl restart`; an `OnFailure=` target that starts or restarts a service, read through what it runs, one script deep, or that can't be read. One that only notifies isn't one (#351). A timer's service is read the same way, so a restart inside the script it runs is found (#368), a relative script path read against the unit's `WorkingDirectory=` as systemd runs it (#418); one running a program the scan can't follow, a binary, `uv run` or a `python -m` module (#393), leaves the scan incomplete until the knob declares it a restarter or `not-restarter:<service>`. A unit hooked to an `OnFailure=` target the scan can't read is a restarter until the knob declares it one or `not-restarter:<target>`, keyed by the target's template, so one line covers every unit hooked to it (#420). Every script line but a comment is matched, a docstring's or a usage string's too, since a restarter missed runs unstopped through a data-store step; the finding names the file and every line it matched, and one where none is a call takes the same `not-restarter:`; a restart on an Exec line takes none (#419). Unit files and scripts are read as root where the user can't, and one even root can't read leaves the scan incomplete, not clean (#360) | a health timer restarting the app, unapproved, during a 1.5 s database outage |
| **Units that `Requires=` a service** | `systemctl list-dependencies --reverse <service>` | a stop and a later `start` leaving the dependent inactive: wslcb's health timer stopped with the app, and only a `restart` brings it back |
| **A backup regime** | timers or cron that dump each data store, and their last success | taking a second dump when a verified off-node regime exists, or assuming one that doesn't |
| The health baseline | each knob `health`, the suite's pass and skip counts, `systemctl --failed`, the timers' last results | no baseline to compare the post-boot state against |
| Callers and traffic | the service's own access or audit log, by UTC hour | a window in the busy hour; a caller whose degraded path is permanent (CannObserv/power-map#589) |
| What reads 200 while degraded | the code path for each dependency down | a fail-open cache hiding the outage, or a caller stamping a 200 `unavailable` as done (CannObserv/wslcb-licensing-tracker#183) |
