It's the **`may-2026`** image, the generation between Feb-2026 and the newer ones, with a local PostgreSQL 16 whose own nightly backup to GCS stood in for the dump. The run was **out of cycle**: the owner took it on a Thursday, outside the knob's Tue/Wed window.

- Posture `scheduled`, window Tue + Wed 16:00–23:30 UTC (09:00–16:30 PDT, 08:00–15:30 PST, so DST moves nothing).

### What the skill got wrong or lacked

- **`git_origin` misses an SSH host-alias remote** (#391), so a tree's owner reads `unknown`.
- **The profile's fwupd fact was dated too narrowly** (#392): a `may-2026` image has it too.
- **The restarter scan labels `python -m <module>` as a relative script path** (#393). The verdict, `unread`, is right; the reason isn't.
- **No apt mode in `prune-plan.sh`** (#370): this was the second by-hand fwupd purge. **Since fixed** (#370): `prune-plan.sh --component apt:fwupd --take-orphans` plans it, and `prune.sh` runs it a stage at a time ([pruning.md](../../pruning.md#any-other-apt-package)).
- **No out-of-cycle window but a knob edit.** An owner taking the monthly run on another day had two choices: commit a window, or pass a copy of the knob with one added (`--config`). The run did the second, and kept the copy in the run directory. The lanes have `origin:<origin>` for a bulletin, but nothing marked a one-off window as one. A dated `window` line has since shipped (#421).

### Decisions

- **The backup line stood in for the dump.** Its object was attested by name.
- **Tailscale was followed**, as its own held step, scoped by a tracked pin file.
- **fwupd was purged, not held:** its units had been masked since the image build, and the VM has no firmware.
- **The run was taken out of cycle on the owner's word,** through a knob copy adding `window Thu 13:45-23:30`. The committed knob was left alone.
- **The run's own files were copied out of `/tmp` before the reboot:** the session's scratch lived there, and the boot clears it.

### Surprises

- **An approval arrived after the window closed.** The owner's approval 2 came 50 minutes after Wednesday's window ended, so the run moved. Nothing was started under it.
- **The security set grew by 3 in a day** (curl among them). A dry run older than a few hours undercounts; the 24-hour limit holds, but the count it gives is a floor.
- **A session's scratch is a `/tmp` path**, and the `D` rule clears it at boot. `reboot-chain.sh` listed 116 staged entries, the run's own files among them.
