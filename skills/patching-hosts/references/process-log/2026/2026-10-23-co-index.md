### What the skill got wrong or lacked

1. **The gate had no out-of-cycle window.** `policy.md` routes a Tailscale bulletin into "an out-of-cycle window: `apply.sh --lane origin:<origin>`", but `apply.sh` applies the `window` check to every lane, and the knob's grammar had no window that wasn't weekly.
   - The run happened on a Friday, outside every window. The only way in was a knob edit committed for the run, `window Fri 13:55-15:55`, and reverted after it (CannObserv/index `e0339be`, `4baebb0`).
   - A weekday line reopens every week until someone removes it, so forgetting the revert would silently widen the host's posture.
   - `--config` with a scratch copy of the knob would also have passed the gate, but no record would show the window had been opened.

   **Since fixed** (#421): a dated `window <YYYY-MM-DD> <HH:MM-HH:MM> [<reason>]` line opens once, stays in the knob's history, and is a `past-window` finding once its day has passed. usa-wa, host 6 and broker each took a temporary weekday line before it shipped ([2026-10-26](2026-10-26-usa-wa.md), [2026-10-26](2026-10-26-host-6.md), [2026-10-28](2026-10-28-broker.md)).
2. **With the origin's only package in a hold group, the bulk takes nothing.** The `origin:` lane's candidates are the origin's packages only, and `hold tailscale tailscale` holds all of them. So the bulk refreshed the lists, recorded the before-versions, held `tailscale` and upgraded nothing; the held step did the work. That made two approvals, two gate passes and two reprobes for one package.
   - The bulk's record has value. What's missing is a warning: neither the dry run nor the bulk's plan says it will take nothing.
   - Proposed: when an origin lane's every pending package falls in a hold group, the dry run's summary and the bulk's JSON say so, and name the held step that will take them. The owner then approves the bulk knowing it is bookkeeping.

   **Still open, tracked as #607.** #488 narrowed the security and maintenance lanes' holds, and named this `origin:` lane shape out of its scope. broker hit it again on [2026-10-28](2026-10-28-broker.md).

### Decisions

- **The origin lane, not a hand run,** because the knob follows the origin. That kept the gate, the before-versions, the reprobe and the run directory (`/var/backups/patching-hosts-20261023T135839Z`).
- **A committed, reverted window line over a scratch `--config`,** so git records that the window was opened.
- **No recovery point.** The knob declares no datastore, and its own note asks for a Qdrant snapshot only before a step that stops Qdrant. Nothing in the set did: both units order `After=` tailscaled only.
- **A Friday afternoon, outside the clients' near-silent hours.** This is a `dev` host, and an outage only degrades search. The `inflight` gate covers a client's index run, and it caught one.

### Surprises

- **None in the step itself:** it matched the hosts measured before it.
- **The inflight gate refused a real index run on its first try,** and released after one drain. That's the first time it held off live work on this host.
