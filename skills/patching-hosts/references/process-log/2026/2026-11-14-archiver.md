### What the skill got wrong or lacked

1. **Under `--no-sudo`, the language audit read `uv audit exited 126`.** That's `as_user` returning 126 because it can't change user without privilege. The tree's `uv.lock` is root's, so it's audited as `nobody`. Nothing in `not_read` said that a sudo probe would read it. **Since fixed** (#635): the `not_read` line names the missing privilege.
2. **A prune stage's soak expiring was a knob finding,** `expired-exception`, from `read-knob.sh`. Watcher's knob test, the template for the cohort, asserts `findings == []` and no expired exception. With a 7-day soak, it goes red in CI for every change once the date passes, even though pruning.md calls that expiry the prompt for the next stage. This host's test now exempts `disabled:` and `removed:` lines. **Since fixed** (#636): a soak's end is its own finding kind, `soak-ended`, which a repo's knob test allows.
3. **The restarter scan asks for one `not-restarter` exception per timer service running `python -m`:** five here, as power-map's twelve the same day ([2026-11-14](2026-11-14-power-map.md)). The template test's per-unit check read only each entry module. This host's test reads all of `src/` for `systemctl` and systemd's D-Bus API, which covers what each module comes to import.

### Decisions

- **The cadence is weekly, not monthly as filed.** The owner widened it when picking the window, Mon 06:00–08:00Z, the one Sunday-evening Pacific slot clear of every other cohort host's window and of this host's quiet ranges.
- **`inflight` reads unit state, not the database:** every timer service is a `Type=oneshot` `archiver-*.service`, so the gate counts the activating ones. The two hourly timers run on `OnUnitActiveSec=` and drift through the hour, so no `quiet` line could hold them. The command reads no env file, and runs no Python with a production URL.
- **`recovery` uses the read-only role,** and proves the outbox is drained. That's weak on an idle host. `/health` is DB-free, and no unauthenticated route touches the database.
- **nginx and docker were pruned in this run's preparation:** the disable stage, then a 7-day soak, then a savepoint and the purge.
- **The tailnet's auto-update switch is the owner's;** the node's went off in the run's preparation.

### Surprises

- **Tailscale had upgraded itself, through a control-plane push,** six days before the run. `c2n POST /update` ran `tailscale update --yes`, and apt's history shows `apt-get install --yes --allow-downgrades tailscale=…` with no `Requested-By`. The node read `AutoUpdate.Apply: true`, though another host's knob records the tailnet switch as off.
- **No apt pins were present** for either followed origin. Both sat at 500 until the run's preparation installed tracked pin files.
- **The reboot re-delivered the setup script at 0755,** with its unit disabled and not run. The post-boot `setup-script:present` finding has no exception key, so containment (`chmod 600`) is a host step after every boot until the image or provisioning stops the delivery.
