### What the skill got wrong or lacked

Both are tracked on #680, and addressed in the same set: the bulk reports what it took uncounted (`upgrade.uncounted`) and the dry run's age, and the chain's `next` before approval 3(b) says how many `/tmp` paths the boot empties.

- **A package published between the dry run and the bulk is taken uncounted, and nothing says so.** The dry run was at 01:04Z, but approval 2 arrived at 05:36Z. In between, noble-security published `libcpanel-json-xs-perl`, and the bulk took it: 90 = 91 − 2 held + 1 new. `verdict.version_moved` covers only held packages, so the extra package appeared only by diffing `upgrade.upgraded` against the dry run's list by hand. Proposal: the bulk lists packages it took that the dry run didn't count (`upgrade.uncounted`) beside `version_moved`, and the dry run's age, so the owner can see a stale count. No refusal is needed, because the space gate re-reads after `apt-get update`.
- **The gate's run span assumes the steps run back to back,** but each held step and the reboot wait on their own approval. Here, approval 3(a) for tailscale arrived about 5.5 h after the window closed (07:00Z), although the bulk's span (05:36 → 06:19Z) fit. The promoted rule (a one-off window when the approval arrives) covered it: a `--config` copy of the knob with `window 2026-11-18 13:00-15:00`, nothing committed. Its `#804` reason was cut at `#` (since fixed, #656).

### Decisions

- **The one-off window went in a `--config` copy, not a commit.** The repo works PR-only, and a commit would have needed merging and pulling to main during the run. The copy was kept in the run dir by hand, which #681 now does for every `--config` knob.
- **The volatile journal was copied before the chain too,** at the owner's request. It held the evidence of an egress outage the day before (power-map#833), and the owner wanted it secured whether or not the chain reached its own last-step copy. Cheap: 25 MiB.
- **Egress was checked before each approval as well as `/ready`:** `getent hosts archive.ubuntu.com` plus a 10 s HTTPS probe. That came from the 11-17 outage, during which DNS failed for 10 minutes. A bulk that can't download fails cleanly, but costs the window.

### Surprises

- **3.33× the dry run, over `bulk-factor 3`.** It joins usa-wa (3.1), co-processor (3.1) and host 11 (4.0) above 3×, on a 90-package set with PID 1 re-exec. The span still fit, but a host whose window is tight should set `bulk-factor`.
- **The operator's own scratch dir was under `/tmp` and went with the boot.** `reboot-chain.sh` listed it in `tmp_staged`, as designed, but the agent didn't read the list out before approval 3(b). Nothing was lost, since the step JSON had been copied to the run dir first. Possibly worth a line in the chain's approval text, "N paths under /tmp will be emptied", so it isn't buried in the JSON (#680).
