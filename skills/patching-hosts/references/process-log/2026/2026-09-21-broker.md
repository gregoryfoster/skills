## Session 2026-09-21 — broker (reading, before the round)

The reading that started #313. A check after CannObserv/broker#35 and #36, which were about Claude Code's update channel, found that broker's production VM had applied no OS security update since it was provisioned, and that nothing on the host said so. Nothing was patched in this session.

### Environment

exe.dev, on the exeuntu image. No profile existed yet. There's no `linux-image` package: the kernel is the platform's, so kernel patches come from exe.dev, not apt.

### Readings

- `unattended-upgrades.service`, `apt-daily.timer` and `apt-daily-upgrade.timer` were all **masked**. The public exeuntu Dockerfile masks them, along with the update-notifier timers, so every VM built from the image starts with patching off.
- Yet `20auto-upgrades` said `Unattended-Upgrade "1"`: **the config claimed patching was on, over a masked unit.**
- The security lists were three weeks old, with 27 security upgrades pending against them. The real count was unknown until a refresh.
- needrestart was installed. No policy was written down in the repo.

### What the profile lacked

There was no profile. This run set its first facts: the masks come from the image, and the kernel from the platform.

### Surprises

It was the same failure as the Claude Code channel: an update channel that looks self-maintaining isn't, and its own config says otherwise.
