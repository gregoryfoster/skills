### What the skill got wrong or lacked

- **The security lane holds what its selection can't take.** The bulk held every pending hold-group package from any origin, so an `-updates` `containerd` cost an unbudgeted held step that upgraded nothing (#488).
- **An out-of-cycle window still meant a weekday line committed and reverted** (#474, its second occurrence). This time the owner's go-ahead reached the host after the temporary line had closed, so it was widened in a second commit. A dated window, as #474 proposed, would have needed the same widening, but not the revert. One has since shipped (#421).
- **A declared `held:` exception with no hold on the host is silent.** The exception outlived the hold through the VM move, and a later `fwupd` update would have reached the conffile prompt the hold exists to avoid. Possibly worth a probe line, "declared held, not held": a finding only once the package is pending, but a note before then.

### Decisions

- **The run went out of cycle, the day before the window,** on the owner's call. A window line was committed for it and removed after (net diff none).
- **The undeclared databases were dropped, not excepted:** nothing read them, and each one is recreated on demand.
- **`fwupd` was re-held first,** with the owner's approval, as on the old VM.
- **The owner approved each step separately:** 0, 1, 2, then 3(a) and 3(b) together.
