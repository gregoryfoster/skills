### What the skill got wrong or lacked

- **The `ordering:` rule assumes every `service` depends on every `datastore`.** On a host whose services are peers, it fires for each one that isn't a client of the store, and needs an exception per service. It could read a dependency, an `After=`/`Requires=` or a `depends` line, before calling a start order luck.
- **The reboot chain stops a unit twice when the knob names it as both a `service` and a `datastore`.** It's harmless, but the chain's text reads as two stops.
- **`probe.sh --lane` without `--dry-run-into` was a usage error.** A last `--refresh-into` probe after a maintenance-lane run is the obvious thing to type; the error said why, though. **Since fixed** (#593, found again on [wslcb-licensing-tracker](2026-11-07-wslcb-licensing-tracker.md)): the after reading takes no lane, and one passed is ignored with a warning.
- **A release landing mid-run is invisible to the run.** The bulk's lists were 56 minutes old at the post-boot probe. Only the record's last `--refresh-into` probe caught it.
- **A dated `window` line's reason can't start with `#N`** (from index#31). `window 2026-11-13 17:20-22:20 #31, …` parsed with `reason: null`, because a `#` after whitespace opens a comment (knob.md's first rule). This run's line had the same form. `index#31, …` printed the reason. knob.md's own example uses a bare token (`TS-2026-013`), so a hint in the dated-window row would help.
